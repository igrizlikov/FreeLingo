# FreeLingo 0.6.12 — восстановление абзацев и TranslateGemma 12B

## Изменения
- При ⌘4, если Accessibility возвращает длинную строку без абзацев, FreeLingo осторожно запрашивает выделение через ⌘C. Использует его только при совпадении содержимого без пробельных символов и наличии переносов. Восстанавливает прежнее содержимое буфера, если его не заменил пользователь. Не получает текст через сеть.
- Журнал теперь содержит `content_hash`: приватный отпечаток без пробелов и переносов для проверки совпадения; `origin=hotkey_clipboard` означает, что абзацы восстановлены через копирование.
- Добавлена экспериментальная TranslateGemma 12B Q4_K_M (~7,3 ГБ), официальный источник весов — Google, конвертация bullerwins; GGUF SHA256 `9196d728812afbf5efc10b539298585725edc3a4ecc092c22fdde5bbaf41879e`. Лицензия Gemma Terms, см. страницу модели.
- «Сравнить ...» позволяет сопоставлять TranslateGemma 4B и 12B, когда обе установлены, без смены выбранной модели.
- Предпочтение пользователя к TranslateGemma 4B сохраняется, автомиграции на 12B нет.

## Ограничения
Неизвестно, предоставляет ли конкретное исходное приложение абзацы через ⌘C. При несовпадении текста или невозможности копирования используется исходный AX-текст, и в журнале остаётся `origin=hotkey`. Закрывать окно источника до завершения резервного копирования нежелательно (~0,25 с).

Компиляция AppKit, установка GGUF 12B и реальная оценка перевода требуют macOS GitHub Actions и теста на Mac. Дополнительно проверь сохранение буфера обмена и Replace.
