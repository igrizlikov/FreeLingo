# FreeLingo 0.6.17 — проверка KV-кэша и скорости

**Основание:** журнал 0.6.16 показал разные result_hash при неизменном source_hash и температуре 0; во вторых вызовах `prompt_n` падал с 435 до 5. Это корреляция, не доказательство причины.

- Настройки → Перевод → KV-кэш 12B: `Обычный` (поведение 0.6.16) / `Без повторного кэша` (эксперимент). Только TranslateGemma 12B. Выбор действует при следующем запросе, перезапуск сервера не требуется.
- Кнопка `Тест KV-кэша и скорости`: 6 переводов *фиксированного несекретного текста* (3 со стандартным кэшем, 3 с `cache_prompt=false`) на одной модели и сервере, независимо от текущей настройки. Сводка показывает скорость, время и устойчивость отпечатков. Подробные данные находятся в журнале (`event=kv_bench`).
- Не менялись квантование Q4_K_M, температура 0, система контроля качества, Metal или потоковый перевод.
- Источник параметра `cache_prompt`: upstream llama.cpp tools/server/README.md. В документации отмечена возможность небольших различий результатов при повторном использовании KV-кэша из-за неидентичных вычислений.
- Запуск теста блокирует движок для других переводов на несколько десятков секунд; кнопка предотвращает повторный запуск.

**Проверки:** исходники/статические unit-тесты в Linux. Потребуются macOS GitHub Actions и тест на Apple Silicon для фактической проверки.

**Ограничение:** `cache_prompt=false` может не обеспечить 100% одинаковые ответы; бенчмарк диагностирует различия, не исправляет их автоматически.
