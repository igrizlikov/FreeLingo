# FreeLingo 0.6.0 — Apple Silicon

Нативное приложение для macOS 15+, Rust + AppKit, локальные GGUF-модели через llama.cpp/Metal.

**Состояние:** изменения в 0.6.0 прошли проверки исходников, но пока не собраны и не проверены на реальном Mac. Уже существующая сборка 0.5.4 не содержит этих функций; для обновления требуется один новый DMG. Дальнейшие обновления могут устанавливаться через Sparkle после настройки подписи.

## Новое в 0.6.0

- **Иконка в строке меню:** контрастная буква F со стрелкой, Template Image с автоматическим переключением под светлую/тёмную тему.
- **Без значка Dock:** «Показывать значок в Dock» в меню строки меню и в «Настройках». При отключении FreeLingo остаётся доступен в строке меню, его окна открываются вручную, приложение не завершается при закрытии окон.
- **Автозапуск:** «Запускать при входе в macOS» настраивается там же через `SMAppService.mainAppService` (macOS 13+). При отключённом Dock FreeLingo открывается в фоне. macOS может запросить разрешение на Login Items; если регистрация отклонена, показывается причина.
- **Обновления:** в меню «Проверить обновления…». Sparkle 2 проверяет appcast по HTTPS, сверяет цифровую подпись EdDSA и устанавливает новый ZIP приложения. Без настроенного публичного ключа пункт честно объясняет, что обновления ещё не активированы.
- Локальные модели не входят в `.app` и хранятся отдельно, поэтому обновление приложения не должно удалять их. Для запуска локального перевода интернет не требуется после загрузки модели.

## Сборка без установки Rust и Xcode пользователю

В репозитории должны быть все файлы, включая `.github/workflows/build-dmg.yml`. В GitHub открой Actions → **Build FreeLingo DMG (Apple Silicon)** → **Run workflow**. После успешной сборки в Artifacts будет `FreeLingo-AppleSilicon-DMG` с DMG и ZIP.

Пользователю достаточно установить DMG один раз. Приложение ad-hoc подписано, но **не нотарифицировано** в Apple (может появиться запрос безопасности). Для глобальных хоткеев потребуется «Универсальный доступ», для OCR — разрешение экрана.

## Настройка полноценных автоматических обновлений — один раз владельцу репозитория

Sparkle не устанавливает произвольные неподписанные обновления. Требуются **пара ключей EdDSA** и публикация GitHub Releases.

1. Один раз получить ключи официальной утилитой Sparkle `bin/generate_keys` из [выпуска Sparkle](https://github.com/sparkle-project/Sparkle/releases/tag/2.9.6). Она умеет `-x <файл>` для экспорта приватного ключа. Ключи создаются локально на доверенном Mac, не в публичном GitHub. Не отправляй секретный ключ в чат и не загружай его в репозиторий.
2. В GitHub → FreeLingo → Settings → Secrets and variables → Actions → **Variables** создать `SPARKLE_PUBLIC_ED_KEY` со значением публичного ключа, который выдала утилита.
3. Там же в **Secrets** создать `SPARKLE_PRIVATE_ED_KEY` с содержимым экспортированного секретного ключа. Храни резервную копию ключа отдельно и не публикуй его.
4. Собрать первую версию с публичным ключом через **Publish signed FreeLingo release** в Actions. Она создаст GitHub Release, подпишет ZIP и запишет appcast.xml в main. Первый установочный DMG этой версии нужно поставить вручную; последующие подписанные релизы будут доступны из приложения.
5. Для следующих выпусков увеличивать `CFBundleShortVersionString` и `CFBundleVersion` в `assets/Info.plist` и запускать **Publish signed FreeLingo release**. Не изменять ключ подписи после первого выпуска без документированной процедуры ротации.

**Не выкладывай приватный ключ в публичные файлы, Actions Artifacts или сообщения чата.** Если ключи не настроены, приложение продолжит работать и переводить текст, но не станет устанавливать обновления из неизвестного источника.

## Тестирование на Mac

1. Скачать и активировать модель (Qwen3 0.6B для начала); убедиться, что приложение не закрывается при 100%.
2. Закрыть главное окно: значок в строке меню остаётся. Выбрать «Показывать значок в Dock» — проверить переключение.
3. Включить автозапуск, проверить «Системные настройки → Основные → Объекты входа и расширения» и перезайти в систему. FreeLingo должен остаться в меню, без внезапного главного окна при скрытом Dock.
4. Проверить `⌘4` в TextEdit, «Копировать» и «Заменить». Убедиться, что при отсутствии разрешения Accessibility приложение не изменяет другой текст.
5. Проверить «Проверить обновления…». Пока appcast/ключ не настроены — увидеть информативное сообщение, а не обещание установленных обновлений.
6. После следующей подписанной версии — выполнить реальное обновление без DMG и проверить, что модель осталась на месте.

Тесты в среде разработки (без macOS GUI): `python3 tests/check_release.py` и `bash -n build-macos.sh`. При необходимости полный macOS CI делает `python3 tests/smoke_macos.py` с тестовой моделью.

Отчёт о реализованности: `replica/features.csv`. Не считать успешную компиляцию подтверждением работы UI на Mac.
