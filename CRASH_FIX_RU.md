# FreeLingo 0.5.3 — исправление падения после загрузки модели

## Наблюдение
На macOS приложение закрывается после того, как загрузка GGUF доходит до конца.

## Причина в коде (вероятная причина именно этого сбоя)
В `native/ModelWindow.inc` после завершения скачивания вызывается `FLHashFile()` на фоновой очереди GCD. В `native/ModelManager.inc` у `FLHashFile()` находился локальный 1-МБ массив `uint8_t buffer[1024 * 1024]`, который может превышать размер стека потока GCD. Это приводит к stack overflow / EXC_BAD_ACCESS.

## Исправление
Буфер чтения SHA-256 уменьшен до 64 КиБ. Это меняет только размер порции чтения, не влияет на проверяемый хеш и загрузку моделей.

```diff
-    uint8_t buffer[1024 * 1024];
+    uint8_t buffer[64 * 1024]; // Keep safely below the small stack of a GCD worker thread.
```

## Как обновить репозиторий GitHub без Terminal
1. Открыть https://github.com/igrizlikov/FreeLingo/edit/main/native/ModelManager.inc
2. Найти `uint8_t buffer[1024 * 1024];` и заменить на `uint8_t buffer[64 * 1024];`.
3. Нажать Commit changes и сохранить в main.
4. В Actions заново запустить Build FreeLingo DMG (Apple Silicon), скачать новый артефакт и переустановить .app.
5. Проверить загрузку модели и перевод. Проверка на настоящей macOS пока не выполнялась.

## Если снова закроется
В окне macOS с ошибкой нажать «Подробнее», сохранить отчёт о сбое и прислать файл. Для диагностики необходимы как минимум `Exception Type`, `Termination Reason`, `Crashed Thread` и верхние кадры стека падения. В отчёте могут быть пути пользователя — по желанию их можно скрыть.

## Состояние частичной загрузки
После падения мог остаться файл с расширением `.part` в `~/Library/Application Support/FreeLingo/Models`. Не удаляйте его до проверки, если он нужен для восстановления; текущая реализация не поддерживает продолжение такого скачивания, поэтому при повторной загрузке файл может быть перезаписан.
